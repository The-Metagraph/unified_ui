# `.spec`

This folder is the repository-local Spec Led layer for the unified monorepo.

<!-- spec.workspace.readme_present -->

## Canonical Layout

- `README.md` (authored)
- `AGENTS.md` (authored, local operating guidance for agents working in this folder)
- `decisions/README.md` (authored ADR guidance for this workspace)
- `decisions/**/*.md` (authored durable cross-cutting ADRs, including governance decisions)
- `specs/spec_system.spec.md` (authored, meta-spec for this folder)
- `specs/package.spec.md` (authored, repository-level intent)
- `specs/governance/**/*.spec.md` (authored governance contracts and policies)
- `specs/**/*.spec.md` (authored subject specs in the canonical Spec Led file format)
- `state.json` (generated by `mix spec.plan` and `mix spec.verify`)

## Local Extension

This repository adds a governance layer on top of the default Spec Led scaffold.

- Durable governance contracts live under `.spec/specs/governance/`.
- Durable cross-cutting rationale remains in `.spec/decisions/` as ADRs.
- A separate conformance layer is reserved for later work and should not be collapsed into governance contracts.

## Core Loop

1. update current-truth subjects under `.spec/specs/`
2. update or add governance contracts when repository-wide policy changes
3. add or revise an ADR only when the change is cross-cutting and durable
4. use Git history and pull requests as the change timeline
5. run `mix spec.verify --debug`
6. run `mix spec.check`
7. run `mix spec.diffcheck` when code, docs, or tests changed
