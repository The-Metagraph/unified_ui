### **Detailed SDLC Plan: Low-Level Graphics Engine via SDL2**

This plan outlines the development of the `DesktopUI.Graphics` module, its NIFs, and the C wrapper for SDL2. The primary goal is to provide a stable, cross-platform, and performant foundation for 2D rendering and input handling.

---

#### **Phase 1: Foundational Setup and Core SDL2 Interaction**

This phase focuses on establishing the build environment, creating the basic NIF structure, and achieving the ability to create and manage an SDL2 window.

| Task ID | Task Description | Deliverables / Success Criteria | Notes & Dependencies |
| :--- | :--- | :--- | :--- |
| 1.1 | **Project Structure & Build Environment** | - Elixir Mix project created.<br>- C subdirectory for NIFs/SDL2 wrapper.<br>- Build system configured (e.g., `Makefile` integrated with Mix, or `CMake`).<br>- SDL2 development libraries identified as a system dependency (e.g., `libsdl2-dev`). | The build system must compile C code into a shared library loadable by Elixir. Consider using a tool like `pkg-config` to find SDL2. |
| 1.2 | **Basic NIF Skeleton** | - A C file (e.g., `desktop_ui_graphics_nifs.c`) with minimal NIF entry points (`load`, `upgrade`, `unload`).<br>- Corresponding Elixir module (e.g., `DesktopUI.Graphics.Native`) that successfully loads the NIF.<br>- A basic Elixir test confirming NIF loading. | This verifies the Elixir-C bridge is functional. |
| 1.3 | **SDL2 Initialization & Window Creation** | - NIFs implemented: `init_sdl()`, `create_window(title, width, height, flags)`, `destroy_window(window_id)`.<br>- Elixir wrapper functions in `DesktopUI.Graphics`.<br>- Elixir script/test successfully creates and destroys an SDL2 window. | `init_sdl()` should call `SDL_Init(SDL_INIT_VIDEO)`. `create_window` returns an opaque window ID (e.g., a resource reference or an index). |
| 1.4 | **Renderer Creation & Management** | - NIFs implemented: `create_renderer(window_id, index, flags)`, `destroy_renderer(renderer_id)`.<br>- Elixir wrapper functions.<br>- Test creating a renderer for an existing window. | `create_renderer` calls `SDL_CreateRenderer`. Returns an opaque renderer ID. |

#### **Phase 2: Core Drawing Primitives and Resource Management**

This phase covers implementing fundamental 2D drawing shapes and managing graphical resources like surfaces and textures.

| Task ID | Task Description | Deliverables / Success Criteria | Notes & Dependencies |
| :--- | :--- | :--- | :--- |
| 2.1 | **Basic Drawing Frame (Clear & Present)** | - NIFs: `set_render_draw_color(renderer_id, r, g, b, a)`, `clear(renderer_id)`, `present(renderer_id)`.<br>- Elixir wrappers.<br>- Test: Create a window, clear it to a specific color (e.g., red), and present it. A window of that color should appear. | This is the "hello world" of graphics. |
| 2.2 | **Shape Drawing Primitives** | - NIFs for: `draw_point`, `draw_line`, `draw_rect`, `fill_rect`.<br>- Elixir wrappers.<br>- Tests drawing various shapes with different colors. | These directly map to `SDL_RenderDrawPoint`, `SDL_RenderDrawLine`, etc. |
| 2.3 | **Advanced Shape Primitives (Circles)** | - NIFs for: `draw_circle`, `fill_circle`.<br>- Elixir wrappers.<br>- Tests drawing circles. | SDL2 doesn't have native circle functions. This will require implementing a simple algorithm (e.g., midpoint circle) or integrating SDL2_gfx. |
| 2.4 | **Surface & Texture Management** | - NIFs: `create_rgb_surface`, `free_surface`, `create_texture_from_surface`, `destroy_texture`.<br>- Elixir wrappers.<br>- Tests creating surfaces and textures. | Surfaces are CPU-side pixel data; textures are GPU-side. |
| 2.5 | **Image Loading (SDL2_image)** | - Integrate SDL2_image library.<br>- NIF: `img_load(path)` (loads to surface).<br>- Elixir wrapper.<br>- Test loading a PNG/JPG image into a surface, then a texture. | Requires SDL2_image dev libraries. |

#### **Phase 3: Texture Rendering and High-Level Drawing API**

This phase focuses on getting images and other textures onto the screen and providing a more convenient Elixir API for drawing operations.

| Task ID | Task Description | Deliverables / Success Criteria | Notes & Dependencies |
| :--- | :--- | :--- | :--- |
| 3.1 | **Texture Copying** | - NIF: `render_copy(renderer_id, texture_id, src_rect, dst_rect)`. `src_rect`/`dst_rect` can be `nil` for full dimensions.<br>- Elixir wrapper.<br>- Test rendering a loaded image texture onto the window. | `src_rect` and `dst_rect` will be Elixir tuples/maps representing `SDL_Rect`. |
| 3.2 | **High-Level Drawing Convenience API** | - Elixir functions in `DesktopUI.Graphics` that simplify common drawing tasks, e.g., `draw_image(renderer_id, image_path, x, y)`, which handles loading, texture creation, copying, and resource cleanup internally or expects pre-loaded textures. | This API is for the framework's internal rendering engine. |
| 3.3 | **Clipping Rectangles** | - NIFs: `set_render_clip_rect(renderer_id, rect)`, `get_render_clip_rect(renderer_id)`.<br>- Elixir wrappers.<br>- Test drawing shapes with an active clipping rectangle. | Essential for UI elements like scrollable areas. |

#### **Phase 4: Text Rendering**

A crucial part of any UI framework. This phase integrates SDL2_ttf for font and text rendering.

| Task ID | Task Description | Deliverables / Success Criteria | Notes & Dependencies |
| :--- | :--- | :--- | :--- |
| 4.1 | **SDL2_ttf Integration & Font Management** | - Initialize SDL2_ttf in NIF `load`.<br>- NIFs: `ttf_open_font(path, ptsize)`, `ttf_close_font(font_id)`, `ttf_size_text(font_id, text, &w, &h)`, `ttf_font_height(font_id)`, etc.<br>- Elixir wrappers.<br>- Test opening a font and querying text metrics. | Requires SDL2_ttf dev libraries. |
| 4.2 | **Text to Surface/Texture** | - NIFs: `ttf_render_text_solid(font_id, text, color)`, `ttf_render_text_blended(font_id, text, color)`. (Consider UTF-8 versions).<br>- Elixir wrappers.<br>- Test rendering text to a surface, then to a texture, and finally to the screen. | `blended` is generally preferred for quality. |
| 4.3 | **High-Level Text Rendering API** | - Elixir functions like `render_text(renderer_id, font_id, text, x, y, color, wrap_length)` that handle the entire process of rendering text at a specific location, including word wrapping if specified. | This will be heavily used by the UI component rendering logic. |

#### **Phase 6: Robustness, Optimization, and Integration**

This phase focuses on making the graphics engine production-ready, stable, performant, and well-integrated with the rest of the framework.

| Task ID | Task Description | Deliverables / Success Criteria | Notes & Dependencies |
| :--- | :--- | :--- | :--- |
| 6.1 | **Comprehensive Error Handling** | - All NIFs check for SDL errors (`SDL_GetError()`) and return `{:error, reason_string}` to Elixir.<br>- Elixir wrappers handle these errors gracefully.<br>- Test error conditions (e.g., loading non-existent font/image). | Critical for debugging and stability. |
| 6.2 | **Resource Leak Prevention** | - Implement robust resource cleanup. Ensure all SDL resources (windows, renderers, textures, surfaces, fonts) are properly destroyed when no longer needed or when their Elixir "owner" is garbage collected (potentially using finalizers, but explicit close/destroy functions are safer). | Use tools like Valgrind (on Linux) to check for C-level memory leaks. |
| 6.3 | **NIF Safety and Concurrency** | - Review NIFs for long-running operations. SDL2 rendering calls are generally fast, but be mindful of blocking the BEAM scheduler.<br>- Use "dirty schedulers" if any NIF performs a potentially long, non-CPU-bound task (less common for direct graphics calls). | NIF crashes can take down the BEAM. |
| 6.4 | **Integration with `DesktopUI.Runtime` Prototype** | - Modify a prototype `DesktopUI.Runtime` to use the `DesktopUI.Graphics` API for window creation, event polling, and rendering based on a simple UI state.<br>- Test the full event loop: poll event, translate, update (mock) state, render (simple shapes/text). | This is the first end-to-end test of the graphics engine within the larger framework. |
| 6.5 | **Performance Profiling & Optimization** | - Profile the rendering pipeline under various loads (e.g., many UI elements, frequent updates).<br>- Identify and address bottlenecks (e.g., too many NIF calls, inefficient texture usage). | TermUI aims for "efficient rendering - double-buffered differential updates at 60 FPS" [[0](https://github.com/pcharbon70/term_ui)]. While a direct comparison is difficult, aim for smooth 60 FPS for typical UIs. |
| 6.6 | **Cross-Platform Testing & Refinement** | - Thoroughly test on all target platforms (Windows, macOS, Linux).<br>- Address platform-specific issues (e.g., HiDPI/Retina display support, default font paths, window manager quirks).<br>- Ensure build scripts work across platforms. | SDL2 handles much of this, but edge cases are common. |
| 6.7 | **Documentation** | - Write comprehensive documentation for the `DesktopUI.Graphics` Elixir module, detailing all public functions, their parameters, return values, and any SDL2-specific considerations. | Essential for maintainability and for other framework developers. |

This detailed plan provides a roadmap for developing the low-level graphics engine. Each phase builds upon the previous one, ensuring a structured and testable approach. The use of an existing library like SDL2 [[30](https://github.com/f1sty/sdl-elixir)] as a foundation, rather than attempting to interface with platform-specific graphics APIs directly, significantly reduces the scope of the C-level development while still providing the desired direct desktop access.
